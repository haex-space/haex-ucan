# `@haex-space/ucan` `0.2.0` — Orthogonal CapabilitySet Migration

> **For Claude:** REQUIRED SUB-SKILL: `superpowers:executing-plans`.

**Goal:** Ersetze die hierarchische `SpaceCapability`-String-Repräsentation durch einen orthogonalen `SpaceCapabilitySet` (Array von `{cap, delegatable}`-Einträgen) und ersetze `satisfies`/`canDelegate`/`capabilitiesSatisfy` durch neue Set-basierte Funktionen. Ziel-Version: `0.2.0`. Publish nach npm. Dies ist **PR-A von 3** in der W4-PR-3-Migration ([[haex-vault:docs/plans/2026-08-14-w4-pr3-capability-migration.md]]).

**Architecture:** Der aktuelle `Capabilities = Record<string, Capability>` mit `Capability = SpaceCapability | ServerCapability` wird zu `Capabilities = Record<string, SpaceCapabilitySet | ServerCapability>` — der Value-Typ wird union: Arrays für `space:*`-Keys, String für `server:*`-Keys. Das TS chain-verify (`verifyDelegationChain` in `src/verify.ts:L94`) übernimmt eine neue `enforceDelegatable(parent, child)`-Attenuation-Semantik, die mit der Rust-Seite (`src-tauri/src/ucan/capability_set.rs`) bit-exakt übereinstimmt. Server-Caps (`server/relay`) bleiben orthogonal zum Space-Modell.

**Tech Stack:** TypeScript, pnpm@10.15.1, tsup, vitest, EdDSA (WebCrypto), semantic-release-Style (existing `scripts/release.js`).

## Design Decisions

### D1 — Wire-Form-Kontrakt mit Rust

**Alt** (`UcanPayload.cap`):
```json
{
  "cap": {
    "space:xyz": "space/write",
    "server:did:key:z6Mk...": "server/relay"
  }
}
```

**Neu** (bit-exakt kompatibel mit Rust `CapabilitySet::serialize` in `capability_set.rs:166-170`):
```json
{
  "cap": {
    "space:xyz": [
      {"cap": "read",  "delegatable": true},
      {"cap": "write", "delegatable": false}
    ],
    "server:did:key:z6Mk...": "server/relay"
  }
}
```

Regeln:
- Space-Resource-Keys (`space:*`): Value ist ein `SpaceCapabilitySet` = JSON-Array von `CapEntry`.
- `CapEntry`: `{"cap": <lower-snake_case-name>, "delegatable": <bool>}`.
- Space-Cap-Diskriminatoren: `"read" | "write" | "invite" | "admin"` — kein `space/`-Prefix im Cap-Feld selbst (das Namespace-Prefix lebt weiterhin nur im Resource-Key).
- Array muss **sortiert** sein nach Cap-Diskriminante (`read < write < invite < admin`) und **duplicate-frei**. Enforced beim Deserialize wie in Rust's `CapabilitySet::from_entries`.
- Server-Resource-Keys (`server:*`): Value ist der bestehende String `"server/relay"` — Server-Caps bleiben single-value.

Rust-Cross-Check: `Cap` in `capability_set.rs:24-31` hat `#[serde(rename_all = "snake_case")]` → gleiche 4 Strings (`"read"`, `"write"`, `"invite"`, `"admin"`). Konvergenz garantiert.

### D2 — API-Neuentwurf `capabilities.ts`

**Streichen**:
- `SPACE_CAPABILITY_LEVEL` (const)
- `satisfies(held, required)` (hierarchisch)
- `canDelegate(delegator, delegated)` (war `= satisfies`)
- `capabilitiesSatisfy(caps, resource, required)` (hierarchisch)

**Neu**:
```ts
export type SpaceCap = 'read' | 'write' | 'invite' | 'admin'

export interface CapEntry {
  cap: SpaceCap
  delegatable: boolean
}

// Invariante: sortiert nach SPACE_CAP_ORDER, duplicate-frei.
// Runtime-Struktur ist `readonly CapEntry[]` (interne readonly).
export type SpaceCapabilitySet = readonly CapEntry[]

// Order-Konstante für sort + display + wire-canonicity
export const SPACE_CAP_ORDER: readonly SpaceCap[] = ['read', 'write', 'invite', 'admin'] as const

// Query
export function holdsSpaceCap(set: SpaceCapabilitySet, cap: SpaceCap): boolean
export function isSpaceCapDelegatable(set: SpaceCapabilitySet, cap: SpaceCap): boolean

// Delegation
export type DelegationErrorKind = 'missing' | 'not_delegatable'
export interface DelegationError {
  kind: DelegationErrorKind
  cap: SpaceCap
}
// null = OK, DelegationError = first-offender in SPACE_CAP_ORDER
export function enforceDelegatable(
  parent: SpaceCapabilitySet,
  child: SpaceCapabilitySet,
): DelegationError | null

// Constructor (parses + validates + sorts) — der einzige Konstruktor.
// Wirft bei Duplikaten oder unbekannten Caps.
export function spaceCapabilitySetFromEntries(entries: readonly CapEntry[]): SpaceCapabilitySet

// Builder für ergonomische Konstruktion in Tests/App-Code
export function spaceCapabilitySet(): SpaceCapabilitySetBuilder
// Chain: .read(delegatable).write(delegatable).invite(delegatable).admin(delegatable).build()
```

Server-Cap-Semantik bleibt trivial:
```ts
export type ServerCap = 'relay'
export type ServerCapability = `server/${ServerCap}`  // 'server/relay'
export function holdsServerCap(held: ServerCapability, cap: ServerCap): boolean
// equivalent to: held === `server/${cap}`
```

### D3 — `Capabilities`-Union-Type + Runtime-Discriminator

**Neu** in `types.ts`:
```ts
export type CapabilityValue = SpaceCapabilitySet | ServerCapability
export type Capabilities = Record<string, CapabilityValue>
```

Discriminator-Konvention: `Array.isArray(value)` → SpaceCapabilitySet. `typeof value === 'string'` → ServerCapability. Explicit type guards:
```ts
export function isSpaceCapValue(v: CapabilityValue): v is SpaceCapabilitySet
export function isServerCapValue(v: CapabilityValue): v is ServerCapability
```

Consumer-Beispiel (haex-sync-server PR-C):
```ts
const held = ucan.capabilities[spaceResource(spaceId)]
if (!held || !isSpaceCapValue(held) || !holdsSpaceCap(held, requiredCap)) { … }
```

### D4 — TS-side chain-walker

`verifyDelegationChain` in `src/verify.rs:L94` prüft heute per-hop:
```ts
canDelegate(parentCap, childCap)  // hierarchisch
```

Neu: pro Space-Resource im Child-Payload:
```ts
const parentSet = parent.cap[resource]
const childSet = child.cap[resource]
if (!isSpaceCapValue(parentSet) || !isSpaceCapValue(childSet)) {
  return { valid: false, error: 'chain-hop: space cap type mismatch' }
}
const err = enforceDelegatable(parentSet, childSet)
if (err) return {
  valid: false,
  error: `chain-hop: ${err.kind} for ${err.cap} on ${resource}`,
}
```

Für Server-Resources: gleiche Semantik wie heute — `held === required`.

### D5 — Deserialize-strictness

`spaceCapabilitySetFromEntries` (der einzige Konstruktor) rejected:
- Duplikate (`{cap: 'write'} × 2`) → `throw Error('duplicate cap: write')`
- Unbekannte Cap-Names (`{cap: 'lol'}`) → `throw Error('unknown cap: lol')`
- Fehlende `delegatable`-Property → default `false` (aber Test dokumentiert Verhalten explizit).

`decodeUcan()` in `verify.ts` verwendet den Konstruktor beim Parse — malformed Payload = decode-Fehler, kein Silent-Accept.

### D6 — API-Removal-Strategie

Alle Deletions in einem Commit (nicht deprecation-cycle) — konsistent mit haex-vault-Regel "no backward compat". Der PR-Body listet die entfernten Exports explizit:

- `satisfies`, `canDelegate` (alt), `capabilitiesSatisfy`, `SPACE_CAPABILITY_LEVEL`
- `SpaceCapability`, `SpaceCapabilities` (const map)
- `Capability` union type (ersetzt durch `CapabilityValue`)

`ServerCapability`, `ServerCapabilities`, `serverResource`, `spaceResource`, `parseSpaceResource`, `findRootIssuer`, `verifyUcan`, `decodeUcan`, `createUcan` — alle bleiben (nicht cap-Wert-abhängig).

### D7 — Version + Publish-Mechanik

- `package.json` `"version": "0.2.0"` (0.1.9 → 0.2.0).
- `CHANGELOG.md` (neu falls nicht vorhanden) mit BREAKING-Sektion.
- Existierendes `scripts/release.js` prüfen — wenn's `npm publish` triggert, per `pnpm release:minor` fahren; ansonsten manuell `pnpm build && npm publish --access public`.
- Vor Publish: `pnpm build` grün (tsup emit) + `pnpm test` grün + `pnpm typecheck` grün.

**Step 3: `spaceCapabilitySetFromEntries` implementieren**
```ts
export function spaceCapabilitySetFromEntries(
  entries: readonly CapEntry[],
): SpaceCapabilitySet {
  const seen = new Set<SpaceCap>()
  for (const e of entries) {
    if (!SPACE_CAP_ORDER.includes(e.cap)) throw new Error(`unknown cap: ${e.cap}`)
    if (seen.has(e.cap)) throw new Error(`duplicate cap: ${e.cap}`)
    seen.add(e.cap)
  }
  const capOrder = new Map(SPACE_CAP_ORDER.map((c, i) => [c, i]))
  return [...entries].sort((a, b) => capOrder.get(a.cap)! - capOrder.get(b.cap)!)
}
```

**Step 4: Builder**
```ts
export interface SpaceCapabilitySetBuilder {
  read(delegatable: boolean): SpaceCapabilitySetBuilder
  write(delegatable: boolean): SpaceCapabilitySetBuilder
  invite(delegatable: boolean): SpaceCapabilitySetBuilder
  admin(delegatable: boolean): SpaceCapabilitySetBuilder
  build(): SpaceCapabilitySet
}

export function spaceCapabilitySet(): SpaceCapabilitySetBuilder {
  const entries = new Map<SpaceCap, CapEntry>()
  const add = (cap: SpaceCap, delegatable: boolean) => {
    entries.set(cap, { cap, delegatable })
    return builder
  }
  const builder: SpaceCapabilitySetBuilder = {
    read: d => add('read', d),
    write: d => add('write', d),
    invite: d => add('invite', d),
    admin: d => add('admin', d),
    build: () => spaceCapabilitySetFromEntries([...entries.values()]),
  }
  return builder
}
```

**Step 5: Query-Helpers**
```ts
export function holdsSpaceCap(set: SpaceCapabilitySet, cap: SpaceCap): boolean {
  return set.some(e => e.cap === cap)
```

**Step 6: `enforceDelegatable`**
```ts
export function enforceDelegatable(
  parent: SpaceCapabilitySet,
  child: SpaceCapabilitySet,
): DelegationError | null {
  // Report first-offender in SPACE_CAP_ORDER — child.entries are already sorted.
  const parentByCap = new Map(parent.map(e => [e.cap, e]))
  for (const cap of SPACE_CAP_ORDER) {
    const childEntry = child.find(e => e.cap === cap)
    if (!childEntry) continue
    const parentEntry = parentByCap.get(cap)
    if (!parentEntry) return { kind: 'missing', cap }
    if (!parentEntry.delegatable) return { kind: 'not_delegatable', cap }
  }
  return null
}
```

```ts
import { enforceDelegatable, isSpaceCapValue, holdsServerCap, isServerCapValue } from './capabilities'
// ...

for (const [resource, childValue] of Object.entries(child.payload.cap)) {
  const parentValue = parent.payload.cap[resource]
  if (parentValue === undefined) {
    return { valid: false, error: `chain-hop: parent lacks resource ${resource}` }
  }

  if (isSpaceCapValue(childValue)) {
    if (!isSpaceCapValue(parentValue)) {
      return { valid: false, error: `chain-hop: type mismatch on ${resource}` }
    }
    const err = enforceDelegatable(parentValue, childValue)
    if (err) return {
      valid: false,
      error: `chain-hop: ${err.kind} for ${err.cap} on ${resource}`,
    }
    continue
  }

  if (isServerCapValue(childValue)) {
    if (!isServerCapValue(parentValue) || childValue !== parentValue) {
      return { valid: false, error: `chain-hop: server cap mismatch on ${resource}` }
    }
    continue
  }

  return { valid: false, error: `chain-hop: unknown value type on ${resource}` }
}
```

```markdown
# Changelog

## 0.2.0 (2026-08-14)

### BREAKING CHANGES

- Space capabilities in UCAN payloads are now orthogonal `SpaceCapabilitySet` arrays
  (`[{cap, delegatable}, ...]`) instead of hierarchical strings (`"space/write"`).
- Removed: `satisfies`, `canDelegate` (old signature), `capabilitiesSatisfy`,
  `SPACE_CAPABILITY_LEVEL`, `SpaceCapability` type, `Capability` union type,
  `SpaceCapabilities` const map.
- Renamed: `SpaceCapabilities` const map → `SpaceCaps` with lowercase values.
- Chain-walker (`verifyDelegationChain`) now enforces `enforceDelegatable(parent, child)`
  per hop instead of hierarchical `canDelegate`.

### New API

- Types: `SpaceCap`, `CapEntry`, `SpaceCapabilitySet`, `DelegationError`, `CapabilityValue`.
- Constructors: `spaceCapabilitySet()` builder, `spaceCapabilitySetFromEntries()`.
- Query: `holdsSpaceCap`, `isSpaceCapDelegatable`, `holdsServerCap`.
- Attenuation: `enforceDelegatable` (returns `DelegationError | null`).
- Discriminators: `isSpaceCapValue`, `isServerCapValue`.

### Migration Guide

- Replace `satisfies(held, 'space/write')` with
  `isSpaceCapValue(held) && holdsSpaceCap(held, 'write')`.
- Replace fixture literals `'space/admin'` with `spaceCapabilitySet().admin(true).build()`.
- Wire form change is coordinated with `haex-vault` (PR-B) and `haex-sync-server` (PR-C).
```
